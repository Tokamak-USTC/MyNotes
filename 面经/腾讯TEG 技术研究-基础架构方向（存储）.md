5. 操作系统八股：
	1. 为什么要有虚拟内存
		- 安全，内存访问权限控制，隔离不同进程间的内存地址。
		- 让程序统一认为自己的地址空间从0开始，而不需要感知物理内存布局
		- 让进程的逻辑地址空间能够远远超过物理地址空间
	2. 讲讲select, poll, epoll的区别，哪个最快？epoll怎么实现？
		- select 是一个固定长度的fd数组，每次都要扫描一整趟来确定哪些fd有事件到达
		- poll 取消了这个fd数组长度的限制，其他记不清了
		- epoll 内部使用红黑树维护注册进来的fd，就绪了就加入就绪链表，epoll_wait()一次就可以拿到所有就绪的fd，并调用其对应的处理回调，是最快的（**可能这个要根据场景回答，不是所有场景epoll都最优**）
	3. 如果epoll事件处理的延迟很高，你怎么排查？-> 使用top确定占用高的线程，perf top查看是否在某个函数/调用栈上花了大量时间来确定是不是热路径上有重操作，把重操作移到异步路径上，顺便讲了 RS 拉路由请求的优化
	4. 为什么进程管理用红黑树，内存管理用链表？-> 这个其实我也不知道他在问啥，我就讲了一下linux的伙伴系统的大致原理，桶+空闲链表，没再追问 
		- 内核为每个CPU维护 **sched_entity（task的子结构）** 的集合，即 **就绪队列**
		- 需要根据每个 task 的虚拟运行时间 **vruntime**，**选择 vruntime 最小的 task 移出集合**并进行调度
		- 调度完成后要**修改 vruntime 并重新加入集合**
		- 还会做一些 task 的 **插入 / 删除** 动作n
		- 综上使用红黑树最合适
6. 网络八股：
	1. TCP为什么要三次握手？两次行不行？-> 两次握手的场景，如果有滞留的第一次握手请求，服务端收到后就立刻分配连接所需的资源并回包，但是客户端可能不会理会这个回包，导致服务端资源一直被占用。
	2. 如果短时间出现大量CLOSE_WAIT，一般是出现了什么情况？-> 我说挥手流程没复习到，不太会
		- **短时间内大量出现 `CLOSE_WAIT`，说明对端已经断开连接，但应用程序没有正确调用 `close()` 释放 socket，意味着代码存在连接泄漏，会导致文件描述符耗尽、服务不可用。**
	3. 如果一个tcp连接频繁断开，你会如何排查？使用什么工具或者命令？-> 不会 
		- **先看连接状态确认是谁断的（ss/netstat），再看应用日志和监控定位原因，最后抓包（tcpdump）定性是应用问题还是中间网络/设备踢掉了连接。**

8. 数据结构：红黑树和B树有什么区别？-> 红黑树是改造优化的平衡二叉树，有根叶黑，不红红，黑路同的性质，保证最长的路径不超过最短路径的2倍，保证树高不失控的情况下减少插入删除时的旋转操作，B树是一种比较胖的树，每个节点可以有多个孩子，可以进一步降低树高度
