## 记忆化搜索

适用场景：

- 状态转移方程很自然，但递推顺序不明显
- 存在大量重复子问题
- 更容易先写出 `dfs(i, j, ...)` 的含义，再用缓存剪掉重复计算

核心思路：

- `dfs(state)` 表示从当前状态出发的答案
- 先处理边界
- 再判断是否命中缓存
- 最后枚举决策，更新答案，并写回缓存

```cpp
#include <optional>
#include <vector>
using namespace std;

// 根据题意定义状态
// 例如: i, j, mask ...
vector<optional<int>> memo;

int dfs(int state) {
    // 1. 先处理边界
    // if (...) return ...;

    // 2. 再判断是否命中缓存
    if (memo[state].has_value()) {
        return *memo[state];
    }

    // 3. 按题意初始化答案
    int res = 0;

    // 4. 枚举决策并转移
    // res = max(res, dfs(next_state));
    // res = min(res, cost + dfs(next_state));

    // 5. 写回缓存
    memo[state] = res;
    return res;
}

int solve() {
    int state_cnt = 0;  // 根据题意修改
    memo.assign(state_cnt, nullopt);
    return dfs(0);
}
```

常见写法要点：

- `optional<T>` 同时表示“是否算过”和“算出来的值”，比哨兵值更干净
- 如果状态不是一维下标，可以先把状态映射到数组下标，或者改用 `map` / `unordered_map`
- 如果状态很多，函数参数要和状态定义严格对应，不要混入无关变量
- 记忆化搜索的时间复杂度一般是 `状态数 * 单次转移复杂度`

## 递推

适用场景：

- 状态定义清楚，且能确定计算顺序
- 需要更稳定的时间/空间控制
- 想从小状态逐步推到大状态

核心思路：

- 先定义 `dp[i]` / `dp[i][j]` 的含义
- 再确定初始状态
- 然后明确“当前状态由哪些更小状态转移而来”
- 最后决定遍历顺序，保证转移时依赖已经算出来

```cpp
#include <vector>
using namespace std;

// 根据题意定义:
// dp[state] 表示某个状态下的最优值 / 方案数 / 是否可达
vector<int> dp;

int solve() {
    int state_cnt = 0;  // 根据题意修改
    dp.assign(state_cnt, 0);

    // 1. 初始化
    dp[0] = 0;  // 根据题意修改

    // 2. 按正确顺序遍历状态
    for (int state = 0; state < state_cnt; ++state) {
        // 3. 从更小状态转移到当前状态 / 从当前状态更新后继状态

        // dp[state] = ...
        // dp[next_state] = max(dp[next_state], dp[state] + ...);
    }

    // 4. 返回答案
    return dp[0];  // 根据题意修改
}
```

递推模板的检查顺序：

1. `dp[state]` 里的 `state` 到底表示什么
2. 初始状态是否和定义一致
3. 转移来源是否覆盖完整
4. 遍历顺序是否保证“先算子问题，再算当前问题”
5. 最终答案落在 `dp` 的哪个状态

空间优化常见形式：

```cpp
for (/* 按题意枚举阶段 */) {
    for (/* 按题意正序或倒序枚举状态 */) {
        // 原地更新 dp
    }
}
```

常见坑：

- 状态定义和转移式看起来都对，但初始化错了
- 01 背包一维优化要倒序，完全背包通常要正序
- 有“恰好”“至多”“至少”这类限制时，非法状态初值通常不是 `0`，而是负无穷
